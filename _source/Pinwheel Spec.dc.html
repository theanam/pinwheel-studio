Pinwheel Studio

An open-source desktop-publishing studio that runs entirely in the browser. Social posts, thumbnails, print and slides — no account, no server, no uploads. Your files stay on your machine.

Local-first
Static site on GitHub Pages. Every feature, including ML, runs on the device.
Portable files
A .pinwheel file is a zip: JSON document plus original assets. Easy to share, diff and archive.
Real templates
8,000+ generated from hand-built layouts, so every template is a normal, editable design.

Principles

  • Nothing leaves the device unless the user exports it. The only network requests are CDN code, Google Fonts and the one-time model download, all cached afterwards.
  • Templates are designs, not pictures. Every preset opens as ordinary text, shapes and frames.
  • One model, many renderers. The same JSON renders the canvas, the thumbnails and every export.
  • Forward-compatible files. Versioned schema, additive fields, migrations run on open.

3. Architecture

A static single-page app with no backend. The code is split into four modules with one-way dependencies. The prototype ships them as plain ES modules. Production builds them with Vite and TypeScript into hashed bundles.

presetsFormats, palettes, type pairings, copy packs, layout functions, catalog generation. Pure, deterministic, no DOM.
render(element model) → React tree. Used by the canvas, thumbnails and export, so what you see is what you export.
ioExport pipeline, .pinwheel pack and unpack, image import, on-device inference. Libraries load lazily on first use.
editorState, history, selection, pointer gestures, snapping, panels. The only stateful module.

Third-party code (lazy-loaded from a CDN, pinned versions)

  • html-to-image@1.11 rasterizes pages through an SVG foreignObject.
  • jspdf@2.5 assembles multi-page PDFs.
  • jszip@3.10 packs .pinwheel files and zips multi-page image exports.
  • onnxruntime-web@1.18 runs inference on WASM, with WebGPU when it is available.
  • qrcode-generator@1.4 encodes QR codes, rendered as one SVG path.

For offline or air-gapped installs, the build copies all of these into /vendor, and a service worker precaches the app shell.

4. Document model

Coordinates are CSS pixels in page space. Elements are stored in a flat list per page, and array order is z-order. Groups are a shared groupId rather than nesting, which keeps hit-testing, snapping and layer lists simple.

Document {
  name: string, w: number, h: number,           // page size, px
  fmt: FormatId | "custom", tpl?: TemplateId,   // origin, enables re-layout
  theme: { bg, ink, accent, accent2, surface, muted, onAccent,
           onAccent2, hi, line, tint, onSurface, display, body, pairId },
  pages: Page[], brand?: BrandKit, created: ISODate
}

           groupId?, locked?, hidden? }

                 lh, ls /*em*/, upper, bg? /*highlight*/, outline?, shadow? }
Shape    Base & { shape: rect|rounded|ellipse|triangle|diamond|star|burst|
                 polygon|arrow|chevron|parallelogram|arch|half|quarter|poly,
                 fill?, stroke?, sw, radius, points, inner, sides, pts?, dash, shadow }
Line     Base & { stroke, sw, dash, arrow }
Image    Base & { asset?: AssetId, origAsset?, mask: none|rounded|circle|arch,
                 radius, cx, cy /*focus %*/, zoom, flip,

Chart    Base & { chart: bar|line|pie|donut, data: {l, v}[], colors[], ink,

Theme roles are what make recoloring possible. Each color in a template is a role value, so swapping a palette maps old role → new role across every element, and contrast pairs (onAccent, hi) are recomputed to stay at WCAG AA or better.

5. The .pinwheel file format

A standard ZIP (DEFLATE). Rename it to .zip and any OS can open it. Assets are stored as the original bytes, not base64.

my-design.pinwheel
├── manifest.json      format, version, app, created, modified, size, page count, asset index
├── document.json      the Document (section 4)
├── thumbnail.png      ≤480 px preview of page 1 (for file browsers, galleries)
└── assets/
    ├── a3k9x2.jpg      referenced by Image.asset / origAsset / Page.bgAsset / brand.logo
    └── a7p1qe.png
{
  "format": "pinwheel", "version": 1, "app": "Pinwheel Studio",
  "created": "2026-09-30T10:12:00Z", "modified": "2026-09-30T11:40:21Z",
  "name": "Plant 10,000 Trees", "size": { "w": 1080, "h": 1080, "unit": "px" },
  "pages": 1,
  "assets": { "a3k9x2": { "path": "assets/a3k9x2.jpg", "mime": "image/jpeg",
                          "name": "park.jpg", "bytes": 412883, "w": 2400, "h": 1600 } }
}
  • Versioning. version goes up only for breaking changes. New fields are optional, and readers ignore unknown fields. migrate(doc, v) runs a chain of pure upgrade steps.
  • Newer files open read-only with a warning rather than being silently corrupted.
  • Garbage collection. Only assets that are referenced get written, so deleted uploads never bloat a file.
  • Fonts are referenced by family name, not embedded, because they're all OFL Google Fonts. v1.1 adds optional fonts/ for user-uploaded fonts.
  • MIME type application/vnd.pinwheel+zip. The PWA registers a file handler so double-clicking a file opens the studio.

6. Preset system

Templates aren't stored. They're generated deterministically from five hand-authored ingredient sets, so 8,000+ templates cost about 130 KB of code and any fix to a layout improves hundreds of templates at once.

How a template is built

  1. The catalog pairs each format with the layouts whose kinds (t, s, d, p, b, c) and aspect classes (banner, wide, square, tall) fit it, 50–100 per format. A format can pin itself to purpose-built layouts (only) or declare a platform safe box that the layout runs inside, as YouTube channel art does.
  2. Each (format, layout, variant) picks a copy pack by stride, then a pairing and palette from that topic's curated preferences. Wedding copy never gets set in a gaming marker font. A layout can name the packs it suits (the invitation frame takes occasions only) and a pack can name the layouts it tolerates or avoids, so memorial copy never lands in a sale burst and a festival never gets a meme layout.
  3. Occasions carry a theme, not just words. Each occasion pack has a signature palette that dominates its variants (crimson and pine for Christmas, emerald and gold for Eid, red, white and marigold for Puja), a set of motifs — snowflakes, reindeer, crescents, lanterns, diyas, lotus, eggs, pumpkins, balloons, cake, rings, doves — drawn as ordinary path shapes from a CC0 library, a background scatter (snow, sparkles, bats, leaves, confetti) and a sample-art scene (winter, night). After any layout runs, a garnish pass sets two or three motifs in corners no text, photo or button occupies; two motif-led layouts and the occasion layouts dress themselves.
  4. The layout runs against a context: u = min(W,H)/100 units, margins, and helpers for text, headings, shapes, frames, buttons, stickers, pills and vertical stacks.
  5. Headline fitting shrinks type until the estimated wrap fits a line and height budget, using each face's width factor, case and tracking. On the canvas, a measure pass then syncs real text heights back into the model.
  6. A seeded RNG, hashed from the template id, drives decorative variation such as Bauhaus tiles and waveforms. The same id always produces the same design.
  7. Multi-page formats follow a story arc. Page 1 is the template's own layout; the rest come from a per-format sequence — a deck opens with an agenda, fills with section dividers, two-column pages and stats, and closes on a call to action; a carousel repeats a numbered point page and ends the same way. Layouts read the page index, so dividers number themselves and each carousel point picks the next item of copy.

Quality rules every layout must pass

  • Text never sits on an unknown photo without a scrim, a band or a solid shape.
  • Accent-colored text uses hi, which falls back to ink when the accent has less than 3:1 contrast on the background.
  • Margins are at least 7u. Nothing important goes into platform UI zones (story top and bottom 12%).
  • Image slots come filled with a procedural sample — a cartoon portrait, a landscape or a product, chosen from the frame's label and shape and drawn as inline SVG in the palette's own colours — so a template reads as a finished design before a photo is dropped in. No stock imagery ships: the sample is a few hundred bytes of vector, and it disappears the moment a real photo lands in the frame.
  • Visual QA in CI renders one template per format × layout to PNG and diffs it against approved baselines.

Adding a layout

def('my-layout', 'My Layout', 'tsp', ['wide', 'square', 'tall'], c => {
  const { W, H, u, m, P, C } = c;
  const k  = c.kick(m, 0, W - 2*m);
  const s  = c.t(C.sub, m, 0, W - 2*m, u*3.4, { color: P.muted });
  const hd = c.hd(C.title, m, 0, W - 2*m, u*14, 3, H*.4);
  c.vstack([k, hd, s], [u*3, u*4], m, H - m);
});   // → +100 templates across every compatible format

7. Rendering & export

  • Canvas. Each page is rendered at 1:1 in page pixels inside a CSS-scaled stage. Overlays (selection, handles, guides, marquee) sit in a sibling layer, so exports never contain editor UI.
  • Fonts. Before export, the Google Fonts CSS for the families in use is fetched, limited to latin and latin-ext subsets, and the woff2 files are inlined as data URIs. The page then rasterizes with the correct glyphs.
  • PNG / JPG. Rendered at 1×, 2× or 3× device pixels. Several pages are zipped with zero-padded names.
  • PDF. One page per design page, sized to the design in px units, with JPEG at 93% quality for small files. v1.1 moves to pdf-lib vector output with embedded font subsets, selectable text and optional bleed.
  • SVG. A foreignObject SVG with embedded fonts. It's faithful in browsers but not ideal for illustration tools; a native SVG serializer is on the roadmap.
  • Empty frames are filtered out of exports automatically.

8. Background removal (on device)

U²-Netp (Qin et al., Apache-2.0) is a 4.6 MB ONNX saliency model that detects the main subject of a photo and returns a soft mask.

  1. Load. onnxruntime-web is loaded on first use. The model is fetched from a mirror list with a progress readout and stored in Cache Storage (pinwheel-models), so later runs work offline.
  2. Preprocess. Resize to 320×320, normalize with ImageNet mean and std, CHW float32 tensor [1, 3, 320, 320].
  3. Infer. Take output d0 [1, 1, 320, 320] and min-max normalize it. A small levels curve (0.08–0.92) cleans the halo.
  4. Composite. Upscale the mask with high-quality smoothing and apply it to the full-resolution original using destination-in. The result is a new PNG asset, and the original is kept as origAsset for one-click restore.

Threads: GitHub Pages can't send COOP/COEP headers, so WASM runs single-threaded (about 0.3–1 s per image). The optional coi-serviceworker shim enables threads, and WebGPU is used when it's present. v1.1 adds the full U²-Net or ISNet as a "High detail" option for hair and fur, plus mask refinement brushes.

10. UI system

Calm and neutral so the user's design carries the color. Warm off-whites, one dark mint accent reserved for primary actions and selection, and a humanist sans for the interface. Every UI color is a token, and a dark palette follows the system setting or the ☾ toggle in the header.

  • Type. Source Sans 3 (400/600/700) for the UI; IBM Plex Mono for dimensions, values and code. 14 px base, 12 px uppercase section labels at +0.06em.
  • Shape. Controls 32–34 px high with 7–8 px radius. Cards 10–12 px radius. Segmented controls on a #F1EEE9 track.
  • Selection. 1.5 px mint outline, round corner handles, pill side handles, rotation knob 14 px below. Hover outline is mint at 55%.
  • Dark mode. Same tokens, second palette: near-black warm surfaces, cream ink, and a lighter mint for outlines and links so contrast holds. Native controls follow via color-scheme. Canvas pages keep their own colors — only the chrome changes.
  • Brand mark. A pinwheel of four sails in mint and ink around an ink pin. Each sail has two straight outer edges and one curved inner edge, rotated — not mirrored — so it reads as spinning. One SVG path, sized from 12 px to the app icon.

11. Performance & accessibility

  • First paint under 1.5 s on a mid-range laptop. Export, zip and ML libraries don't load until they're used.
  • Gallery thumbnails are live renders of the model (no images), memoized per template and size and paged 48 at a time. Production adds virtualization and an IntersectionObserver.
  • 60 fps drag on pages with fewer than 300 elements. History snapshots are JSON strings, and continuous controls merge into one undo step every 900 ms.
  • Imported images are downscaled to a 2,400 px long edge. Autosave skips assets once the payload passes about 4.5 MB (IndexedDB in production).
  • Every control is a native button, input or select with a visible focus ring and title tooltips. Canvas elements will get an accessible layer tree (v1.1). UI text meets 4.5:1.

12. Hosting & deploy (GitHub Pages)

# .github/workflows/pages.yml
on: { push: { branches: [main] } }
permissions: { pages: write, id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: github-pages
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci && npm run build          # vite build --base=/pinwheel/
      - run: npm run test:visual                # template baseline diffs
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
      - uses: actions/deploy-pages@v4
  • All paths are relative, so the app works under user.github.io/pinwheel/ or a custom domain.
  • A PWA manifest and service worker make it installable and able to work offline, with a file handler for .pinwheel.
  • The CSP allows only the pinned CDN hosts, fonts.googleapis.com, fonts.gstatic.com and huggingface.co. Self-hosting mode removes all third-party hosts.
